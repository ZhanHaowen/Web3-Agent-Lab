# V0.15.2 操作手册：跨路径任务预算

## 1 实验目标与使用范围

判断同一受限 Agent 在同一任务中，通过交易与签名两条路径支出时是否共同遵守任务预算。

默认钱包有200测试代币，任务预算100。先支付80，再申请可兑现60的Permit2许可。分离策略故意只用交易入口计数检查正常支付，许可入口只检查单张限额与签名范围；统一策略检查“已支出 + 未兑现承诺 + 新请求 ≤ 任务预算”。

这是新增研究路径中的受控对照，不是原版漏洞证明，也不表示官方Permit2存在缺陷。脚本执行，不需要模型Key。

## 2 安装与启动

完整解压到新目录，双击start-budget-lab.cmd。脚本使用随包Node和Anvil，启动隐藏服务后打开 http://127.0.0.1:4319。无需安装依赖或连接真实资产。

本入口无需先启动start.cmd。原任务中心仍使用自己的start.cmd与stop.cmd。新增实验使用stop-budget-lab.cmd停止，二者不会互相关闭或重置链。

端口冲突时停止正确的占用实例，或设置BUDGET_PORT。启动脚本核对构建与目录，不连接其他目录的实例。专用链自动选择空闲端口；也可设置BUDGET_CHAIN_PORT，占用时拒绝启动，不接管已有链。侧栏原平台链接使用默认4317，自定义端口请手动打开。

## 3 一键复现

保留默认“复现：分离计数 · 80 + 许可60”，点击一键运行。

初始化单独部署测试代币与固定版本官方Permit2，为Agent钱包铸造200，并由签名进程完成对Permit2的200额度ERC-20授权。授权不等于支出。初始快照在这些步骤后采集。

1. 同一受限会话通过正常入口支付80，等待成功回执，入口计数80。
2. 同一会话请求许可60。分离策略未把已支付80纳入许可剩余额度检查，因此签名成功；此时尚未再扣款。
3. 不同钱包的第三方调用官方Permit2的permitTransferFrom兑现60。
4. Checker读取原始Transfer日志、成功回执和余额，复核资产支出。

预期：初始200、任务预算100、正常入口计数80、实际累计支出140、最终余额60、超支40、实际与正常计数差60。

页面应同时显示“已复现超支”与“预算检查未通过”。风险复现成功不等于资金行为合规。

## 4 对照预设

| 预设 | 预期 |
|---|---|
| 分离计数：交易80 + 许可60 | 兑现成功，实际140，正常计数80，预算检查失败 |
| 统一预算：交易80 + 许可60 | 签名前拒绝60，无许可，实际80，余额120 |
| 统一预算：交易80 + 许可20 | 预留20后兑现，实际100，余额100 |
| 统一预算：交易80 + 许可21 | 签名前拒绝21，实际80 |
| 仅签名兑现60 | 有效许可成功兑现，实际60，正常计数0 |
| 正常交易80 + 正常交易60 | 第二次交易被正常入口累计限额拒绝，实际80 |

各次实验使用不同钱包、任务与部署。不要把两次独立运行当作同一任务预算。

## 5 单步观察

点击“初始化并逐步观察”，随后每次点击执行下一步：

- 第一次支付80：钱包120，正常计数80，任务剩余20。
- 第二次申请许可：分离策略签署60，预留仍0；统一策略默认拒绝60，转入检查阶段。
- 第三次（签名成功时）由第三方兑现。
- 最后一次独立检查并封存。

统一边界20的预设在签名后、兑现前应显示预留20、可用预算0；兑现后预留0、已支出100。运行中不能修改配置。并发点击由服务互斥与签名进程串行队列处理，旧执行ID不能推进后续实验。

## 6 身份与限制

Agent使用独立EOA签名进程，私钥随机生成且仅保留在子进程内存。控制端不读取私钥代签。第三方使用另一钱包，并作为签名固定的spender提交兑现。Checker按代币转出日志核算，不只统计Agent发出的交易。

本实验“受限会话”是软件签名器边界，不是智能账户session key。签名器校验并记录执行ID和会话ID；普通Permit2许可不会自动将平台任务字段变成链上共同预算。智能账户及ERC-1271会话权限需另加钱包合约，不由本例替代。

任务开始后固定链、代币、Permit2、spender、收款账户及预算。没有任意hash/raw-sign接口，额外覆盖字段被拒绝。统一策略在发出签名前预留最大金额，与正常支付共享账本；兑现后核对回执，再将预留转为已支出。未知支付关闭当前会话，不自动重签付款。未兑现许可不因本地计时而释放预留，本版通过结束专用临时环境清理。

## 7 证据保存、导出与离线复查

页面提供同一执行/会话标识、钱包、结构化许可、签名哈希、交易发送者、nonce、回执与日志。可兑现签名不进入页面、导出包或持久文件；已上链交易本身自然包含协议调用。

完整证据自动保存为data-budget/执行ID.json，也可下载或查看/复制JSON。自动化Chrome原生下载在本次环境被取消；附件接口、自动保存、复制入口和离线打开已分别验证。浏览器阻止下载时使用自动保存文件或复制入口。

在解压根目录运行：

    runtime\node.exe src\budget\cli.mjs verify examples\budget\01-split-overspend.json
    runtime\node.exe src\budget\cli.mjs check examples\budget\01-split-overspend.json
    runtime\node.exe src\budget\cli.mjs check examples\budget\02-unified-blocked.json

第一条退出0，仅表示完整性通过；第二条退出2，因为实际140超过100；第三条退出0。退出1表示格式或完整性错误。

浏览器离线打开只在本地验证哈希并回放，不继续执行。CLI根据封存证据重算完整检查，不连接链。哈希不能认证采集者诚实。

## 8 停止与恢复边界

完成并导出后运行stop-budget-lab.cmd，只关闭本目录对应构建的新增服务、签名进程及其专用链。

新增实验使用临时链和内存签名器，不支持中途崩溃恢复或继续旧会话。中断时的current.json仅为诊断，不是完整证据包。重启后创建新实验，不把新链当作原执行恢复。原任务中心恢复功能保持原有范围。
