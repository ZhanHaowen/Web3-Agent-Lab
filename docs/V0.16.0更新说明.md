# V0.16.0 更新说明

本版在 V0.15.3 的 Agent/工具/链/检查器之上增加本地 Qwen3 4B 推理，同时保留 API 模型后端。目标是让研究者控制模型字节和运行参数、降低重复实验的接口成本，并完整获取实际接口与执行数据；不保证 4B 模型完成所有多步骤任务。

## 新增能力

1. 受平台管理的 Qwen3-4B-Instruct-2507 Q8_0 + llama.cpp。显式导入/下载、固定 SHA、动态库指纹、loopback、进程归属验证、启停与配置界面。实验忙碌或本地 worker 在线时拒绝替换/停止推理服务；不接管其他监听进程。
2. 原单 Agent、双 Agent、服务购买、任务中心独立 worker 的模型配置提供 API/local 选择。角色可混合使用后端。脚本基线保持独立，不会触发模型启动。
3. 原单 Agent 与多 Agent 统一原生模型采集：实际请求和响应正文、解析对象、错误/断流前缀、调用 ID、usage 状态、运行参数。完整本地模板、运行 manifest 和日志快照随实验包导出。
4. GUI 可查看原始模型证据和文件引用，下载原生证据子集；离线导入不重新调用模型。旧数据缺失明确标记。详细字段见[数据约定](V0.16.0原生模型数据.md)。
5. worker 失败命令也持久化决策和成本。已写入 checkpoint 的命令重传或重启后不重复推理；Agent profile 中的温度与后端身份不被任务默认值覆盖。
6. 多 Agent GraphML 保留关系类型、角色、事件引用和完整记录，与 JSON/CSV 一起支持溯源分析。

## 构建变化

`vendor/legacy-source/src/` 不再只是不可用的旧快照：V0.16 构建从这份保留的 TypeScript 源码重建单 Agent server/CLI，再组合控制、场景、预算和模型 ESM 模块。历史 `vendor/v013-server.mjs` 与历史报告保持原字节，不覆盖成新结果。

依赖版本及锁文件不变。`build-info.json` 同时固定当前源码与 dist 输出摘要。`doctor` 验证当前构建完整性，并列出与 V0.15 历史摘要的差异。旧“所有源码必须保持 V0.15 哈希”断言改为“当前源码/产物匹配本次构建且历史合约未变”，以检验明确授权的新功能，不能拿历史报告替代本次回归。

## 保留边界

- 本版不替换合约、金额语义、原任务验证规则及原始记录/派生数据分层。
- 任务中心五种原任务模板仍采用脚本适配；模型任务从单 Agent 页面运行。服务购买仍是原场景执行方式。没有宣称完成新的服务交易 worker 架构或大规模并发能力。
- 本地模型支持不等于所有任务都能成功。失败同样保留并由独立检查器判断；本版没有脚本自动补做模型遗漏的交易。
- Git 不含模型权重、实验账户秘密或本机运行数据。预先准备资源后可完全离线执行本地链/本地模型任务；分叉或外部 API 仍按配置联网。
- 真实外部商业模型是否实测、macOS 是否实测、各回归集合结果，均以[本次回归报告](V0.16.0回归测试报告.md)为准。

使用方法见[双后端操作指南](V0.16.0本地模型与双后端操作指南.md)。升级前保留原软件包和 data；旧实验继续用其原版本核验和回放，V0.16 新实验使用新的构建身份。
