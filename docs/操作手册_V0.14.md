# Web3 Agent Lab V0.14 操作手册

V0.14 Peer Beta 在 V0.13 Windows 发布包上增加双 Agent 原子换币实验。Maker 和 Taker 使用独立钱包、独立模型历史与私有目标，通过本地消息总线询价、报价、接受或拒绝；成交使用本地 EVM 托管合约。原 V0.13 单 Agent 页面、API 和历史实验包读取路径继续保留。

## 启动与第一次成交

1. 关闭旧版本，用 stop.cmd 停止后台服务。将新 ZIP 完整解压到新的可写目录，不覆盖原目录。
2. 双击 start.cmd，浏览器打开 http://127.0.0.1:4317。
3. 点击左侧“双 Agent 原子交易”，或打开 http://127.0.0.1:4317/scenarios.html。
4. 点击“初始化实验链”。保持脚本基线、独立实验、自动出块、双方成交，金额保持默认。
5. 点击“创建并运行新场景”。正常结果是 settlement confirmed、business filled、双方目标 success。
6. 查看资产表：Maker 从 100A/0B 变为 90A/20B；Taker 从 0A/100B 变为 10A/80B；托管归零。
7. 点击消息和交易查看证据，导出完整场景包。使用 stop.cmd 关闭服务。

本包携带 Windows x64 的 Node 和 Anvil，无需安装 Node、Python、Docker 或 Solidity 编译器即可运行。GUI/RPC 默认只监听本机 4317/8547。多实例应使用不同 LAB_PORT、LAB_CHAIN_PORT 和 LAB_DATA_DIR。

## 交易是怎样完成的

Taker 发询价，Maker 按自身目标报价。Taker 可接受、拒绝或还价，另一方也必须明确接受还价。协调器只提供轮转运行机会，不替双方决定价格。Maker 精确授权卖出币，createOrder 将 TokenA 锁入 LabPeerExchange；随后向 Taker 发送订单引用。Taker 的 inspect_order 工具从链上核对双方地址、币种、金额、期限、scope、代码哈希及 Open 状态，再授权 TokenB 并 fillOrder。

fillOrder 在同一笔交易内把 B 从 Taker 付给 Maker，把托管 A 交给 Taker。任意必要转账失败则整笔回滚。先前已成功的授权和创建订单不会随 fill 失败自动撤销。

工具的模型签名身份由运行时固定，不能在参数中选择其他钱包。新场景写入路径执行完整角色与订单条款检查；旧 V0.13 单 Agent 路径保留原行为，不能据此认为旧路径的所有安全问题已修复。

## 两种执行方式

脚本基线不调用模型，用固定有效报价验证基础设施。模型模式为两方分别填写 Base URL、模型名称、API Key 和可选系统提示词；它们可以使用相同模型，但拥有不同历史和工具权限。远程模型要求 HTTPS，本机接口允许 HTTP。端点会追加 /chat/completions，必须支持工具调用。

每方仅直接获得自己的私有目标；对方消息可能间接透露信息。密钥通过请求头发送给所配置的模型服务，不发送给对手。模型请求和输出会被记录，API Key 字段和已知密钥值会脱敏。不要在提示词正文填写真实秘密。

模型应通过 send_message 协商，wait 让出执行机会，finish 表示终止业务决定。查询订单、创建、授权和成交都使用对应工具。没有工具调用的自然语言回复不会自动算成交。

脚本样例和标为 protocol-fixture 的模型替身用于验证程序，不是实际云模型能力评测。包内没有真实云模型成功率结论。

## 目标与报价

Maker 的 sellAmount 是本次要卖出的 A，minBuy 是最低接受的 B；Taker 的 minReceive 是最低获得 A，maxPay 是最高支付 B。数量为最多 6 位小数的正十进制字符串。工具层只换算一次，10A 对应 10000000 最小单位。禁止科学计数法、负数与浮点价格比较。

默认双方目标为 10A 对 20B。把 Maker 最低获得改为 21、Taker 最高支付保持 20，脚本会正常拒绝，不创建付款。若预期结果选择“正常拒绝”，独立检查可将这个明确的不成交结果判为符合预期；若预期仍为成交，则业务结果为 no_deal、实验验收为 failure。

## 独立与连续实验

独立实验恢复整条链的标准基线，并部署新的 scope 交换合约，清空本轮消息与交易状态。连续实验继承当前场景环境、账户余额及授权，使用新订单 salt。连续模式仅在同一服务进程及同一链实例内可用；先完成一个独立场景再使用连续模式。

“从初态创建重跑”创建新的 scenarioId 和 episodeId，并关联 parentScenarioRunId。它不修改旧包；模型模式需重新提供必要密钥，模型结果不保证相同。不能用重跑冒充继续处理同一个已付款订单。

V0.13 的链快照不包含新场景的模型历史、收件箱和调度游标。本版不支持跨进程任意检查点续跑，也不允许活动场景中单个 Agent 重置链。服务重启后的历史场景按只读档案处理；不得静默恢复付款。

## 单步与暂停

“每步由我推进”使场景等待“单步”。一次场景 step 选择一方完成一次决策和一个工具动作；等待消息的一方让出机会。多工具模型响应会按本方待处理队列逐个执行。

可以分别暂停 Maker/Taker，也可以在完整运行步边界全局暂停。工具前和交易提交前暂停会显示准备动作。继续按钮恢复当前暂停门；单步模式下需要继续按单步推进。单个钱包的交易提交串行，场景外层持有链锁，其他单 Agent 运行及环境重置会被拒绝。

停止表示停止新决定，不等于撤销交易。已广播交易可能之后入块；Pending/Unknown 会继续保留对账要求。交易意图包含 actor、nonce、calldataHash；广播响应丢失时先按账户与 nonce 搜索，createOrder 还按原 salt 查订单，不换新 salt 自动锁款。

## 手动出块与退款

关闭自动出块后，批准、创建和成交都可能先处于 pending。点击“出块并对账”，按实际区块和回执推进，再运行下一步。区块数与每块秒数分别配置，事件中保存实际起止时间。

Open 订单在 block.timestamp < deadline 时可由 Maker 取消；到期后任何人可调用 expireOrder，退款始终给 Maker。达到期限本身不会发送交易。界面“清退过期订单”会发起清退；若未到期，合约拒绝。取消与成交竞争按真实入块顺序决定，先成功者占用终态，后者回滚。

停止后仍 Open 的订单可在当前环境中使用取消或清退按钮处理。场景或链已被重置时，旧订单操作会因链实例不一致被拒绝；旧档案仍可离线阅读。

## 证据与检查

界面分别显示结算状态、业务结果、双方目标、证据完整性与实验验收。交易 confirmed 不自动代表双方目标满足。检查覆盖角色地址、合约、订单条款、一次成交、四项资产变化、Token 总供应、托管余额、同笔 fill 的两次 Transfer 和成交期限。

同一场景使用一个顺序 JSONL 日志和 SHA-256 内容寻址负载。发送、投递、消费与去重分别留证；模型工具 ID 使用 agentRunId 命名空间。图中包含 Agent、钱包、模型、工具、消息、报价、订单、交易和可获得的 EVM 调用。关系来自显式引用，未取得 trace 时记录 unavailable，不生成虚构调用。

完整导出包的 files 包含 scenario.json、raw/events.jsonl、raw/blobs、environment、labels、derived/graph.json、GraphML、节点关系 CSV、执行轨迹和 manifest.json。浏览器“离线打开场景包”先验证文件哈希，再读取本地内容，不调用模型或链；执行按钮禁用。旧 V0.13 包请在原“实验档案”中打开。

命令行离线操作，均不启动服务和链：

```powershell
.\runtime\node.exe scripts\peer-offline.mjs verify examples\peer-v014\01-scripted-filled.json
.\runtime\node.exe scripts\peer-offline.mjs replay examples\peer-v014\01-scripted-filled.json
.\runtime\node.exe scripts\peer-offline.mjs check examples\peer-v014\01-scripted-filled.json
```

哈希证明包内一致性，不证明采集器诚实、节点可信或发布者身份。模型内部思维不在采集范围。

## 安全和实现边界

仅用于本地测试资产。开发账户密钥公开，不能存入真实资金；不要把 GUI 或 Anvil 管理 RPC 暴露公网。同进程独立对象和对话不是敌对代码安全沙箱。

本次发布固定两个经济 Agent，不接受额外 Agent 配置，不提供开放市场、多链、部分成交、手续费、升级代理或管理员任意提款。服务购买、外部 A2A、x402、AP2 和身份声誉协议不在本版范围。

LabPeerExchange 使用本地最小重入锁与可选返回值 ERC20 转账检查，限制两种不可变 LabToken。没有引入 OpenZeppelin 包，也没有声称经过第三方审计。只能据此验证该实验合约，不能推广为任意 ERC20 的兼容与安全结论。

交付为 Windows x64 包。原有 macOS 启动文件作为历史兼容材料保留，但本包不含 macOS 原生运行文件；不可把 Windows EXE 用作 Mac 交付。本次未进行 Mac 实机测试，未运行真实云模型评测。

## 源码与重建

src/scenario 下提供新增功能的可执行 ESM 源码。vendor/v013-server.mjs 原样保留原 V0.13 发布 bundle；原包未提供的 12 个 TypeScript 源文件未被编造补齐。scripts/build-v014.mjs 对固定兼容锚点做显式桥接并生成构建清单，锚点不同则停止。

新增合约使用 solc 0.8.30，viaIR、optimizer runs 200、Cancun。运行包已含 ABI 与字节码，运行时不需要编译器。开发者重新编译时需官方 solc 包，并把 SOLC_JS_PATH 指向 soljson.js 或 solc 入口：

```powershell
$env:SOLC_JS_PATH='E:\新建文件夹\package\soljson.js'
.\runtime\node.exe scripts\compile-peer.mjs
.\runtime\node.exe scripts\build-v014.mjs
.\runtime\node.exe --test tests\scenario-core.test.mjs
.\runtime\node.exe tests\peer-contract.mjs
.\runtime\node.exe tests\peer-integration.mjs
```

测试使用独立端口和数据目录，多次重置测试链。不要指向已有研究实验的数据目录。测试详情见 docs/v014-contract-results.json、v014-integration-results.json 和 v014-acceptance.json。历史 docs 中 V0.13 测试报告仍属于原版，不是本次验证证据。
