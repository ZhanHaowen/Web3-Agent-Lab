# V0.14.2 更新说明

沿用 V0.14.1 左侧配置、右侧结果的界面。

- 修复接受报价消息省略 payload 时被工具 schema 拒绝的问题；仅无业务字段的消息允许省略，报价金额与接受对象 quoteId 仍严格校验。
- 每轮提供平台核实的阶段、可用操作、已收到的报价和上次工具错误，引导模型恢复。未创建订单时不提供检查订单工具；双方接受前不提供创建订单工具。网关仍做独立检查。
- 自然语言中声称“已接受”不会触发接受或交易，必须调用真实工具。
- 两个 Agent 可使用相同模型、Base URL、API Key；钱包、会话历史和私有目标分别隔离。
- 新增总耗时、模型调用、工具调用与交易次数。计时包含协商、暂停和等待；运行结束后冻结，并写入实验包。历史包没有计时字段时显示破折号。
- 按钮新增按下加深、加载文字与旋转提示；运行和请求期间防止重复启动。显示当前协商阶段与停止原因。

## 使用与验证

关闭旧版服务，将压缩包完整解压到新目录后运行 start.cmd。不要覆盖正在运行的旧目录。先用脚本基线运行默认 10A 换 20B：Maker 最终90A/20B，Taker最终10A/80B，托管余额为0。再切双 LLM Agent 填入支持工具调用的模型接口。相同 Key 可以用于两方，也可能共享供应商并发额度。

点击开始实验后，按钮应立即变深并显示初始化文字；运行期间耗时持续增加，结果出来后停止。启用交易前暂停，可验证暂停期间持续计时、恢复后继续运行；停止后不应残留可恢复的暂停状态。

## 本次验证范围

10项核心单元测试、10项真实本地链 API 场景回归、13项合约/网关测试；另做浏览器按钮加载色与计时检查，以及压缩包解压启动与历史单Agent验证。具体结果见 v0142-unit-tests.txt、v014-integration-results.json、v014-contract-results.json、v0142-ui-results.json、v0142-package-smoke.json。

模型恢复用本地 OpenAI 兼容协议夹具复现：提前创建/检查订单报错、文字假接受、缺 payload 的真实接受，再完成链上交割。夹具不是云端 glm-4-flash 实测；模型供应商的输出质量和并发限额仍可能影响结果。没有使用或打包任何真实 API Key。
