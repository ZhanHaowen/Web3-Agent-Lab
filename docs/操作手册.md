# Web3 Agent Lab V0.18.1 操作指南

本页是当前平台的入口指南。完整的 Windows x64 Release ZIP 自带运行程序；将其解压到新目录后双击 `start.cmd`。默认访问 `http://127.0.0.1:4317`，通过侧栏进入不同模块，完成后运行 `stop.cmd`。任务中心管理入口可用 `open-task-center.cmd` 打开。源码仓库不含便携运行程序，开发步骤见[首页](../README.md)。

| 发布任务，再给 Agent 分配角色执行 | 任务与 Agent 中心 | [V0.15.1 手册](操作手册_V0.15.1.md) |

| Buyer 购买 Provider 的服务，由 Evaluator 参与评估 | 购买 Agent 服务 | [V0.15 手册](操作手册_V0.15.md) |

“分角色”把谁发起任务、谁提供服务、谁判断结果和谁能动用哪一个钱包分开。角色名本身不授予工具或资金权限；实际执行仍要检查所分配任务、工具权限、签名主体和链上效果。默认双 Agent 场景共享本地链与记录器，各自保留模型、对话、提示词、钱包、收件箱及成本记录；本版不承诺大规模并发。原服务购买模块仍采用 V0.15 架构，不能将它等同于任务中心的独立 worker 系统。

## 运行跨路径预算实验

1. 进入“跨路径资产授权与预算控制”，选择并配置本地 Qwen3 4B 或兼容 API 模型。当前页面运行模型 Agent，旧“分离计数”分类入口不再使用。
2. 填写任务、初始余额和任务总预算；在“业务目标”中选择逐笔或累计核验，填写两条路径金额并勾选已核对目标。
3. 选择本地受限 EOA 或本地智能账户（ERC-1271），核对直接转账、Permit2 权限和钱包请求额度。两条路径始终受共同预算约束，未兑现许可预留全额。
4. 在“额外授权约束”设置固定有效期（默认24小时）、白名单、风险实验标签和违规处置。人工确认仅允许本次白名单／风险例外，不能放宽预算或到期限制。
5. 点击“初始化并逐步观察”，再用“执行下一步”查看模型提议、网关判断、钱包执行、第三方兑现及最终检查；也可选择“运行 Agent”。

超额案例可填余额200、预算100，任务与已确认业务目标为直接支付80 BUD、Permit2兑现60 BUD。若模型先完成80再请求60，第二笔应被拒绝；不能改成80与20并将原任务记为完成。模型也可能提前停止，此时须按实际轨迹区分“没有提出请求”和“请求被执行层拒绝”。预算内对照使用40与50，完整执行时累计支付90、最终余额110。详细操作见[V0.18.1预算指南](V0.18.1-BUDGET-GUIDE.md)。

实验使用本地 Anvil、六位小数 BUD 测试代币和官方 Permit2。前置 ERC-20 授权不是实际支出；有效期不是滚动24小时消费限额。白名单与风险标签由实验网关执行，不代表外部钱包已出现越权或生产协议存在漏洞。

## 保存与复查

预算证据默认保存到 `data/budget/执行ID.json`，设置 `LAB_DATA_DIR` 时随数据目录改变。页面支持下载、查看/复制 JSON 和离线打开；离线不会重新调用模型或链。其他模块的实验包见[证据格式](trace-schema.md)，务必选对应 CLI。

升级前先停止旧实例并备份数据，完整解压新版。预算链为临时链，不支持中途崩溃后继续；已导出的证据可离线读取。已有 V0.15.2 证据可读，不会自动迁移旧的 `data-budget` 运行目录。当前为 V0.18.1 Testnet Beta 候选发布，实际验证见[本版记录](releases/V0.18.1-validation.json)；旧版限制和历史验收见[验证说明](validation.md)。
