# Web3 Agent Lab 操作手册

版本：V0.13 Beta（程序版本 0.1.3；修订 beta-1；检查器 2.2.0）｜日期：2026-10-19｜适用对象：课题组实验人员与平台维护者

V0.13 根据实际测试反馈完善图交互、档案检索、模型与任务配置记录、手动出块时间、自定义金额目标及 Agent 续行。详细问题对应、验证方法和边界见[版本说明 V0.13](版本说明_V0.13.md)。旧 V0.12 材料保留原名。

本软件提供本地浏览器 GUI，运行单 Agent 与 EVM 链交互实验，记录配置、模型消息、工具调用、交易和链上证据。Windows 与 macOS 使用同一套程序与数据格式；Windows 包适用于 x64，macOS 包同时附带 Apple Silicon 和 Intel 的运行文件。

## 1. 安装与启动

部署包已包含运行程序、Node.js、Anvil、编译好的实验合约与依赖打包结果。日常使用无需安装开发工具或 Docker。本地链及脚本基线不需要外部 API；连接远程模型或主网分叉时需要网络和相应服务权限。

**Windows：** 将 Windows x64 ZIP 完整解压到具有写入权限的目录，如 `D:\Web3AgentLab`；不要直接在压缩包内运行。双击 `start.cmd`，浏览器会自动打开。浏览器未自动打开时，手动访问 `http://127.0.0.1:4317`。服务在后台运行，启动窗口可关闭；双击 `stop.cmd` 结束服务。

**macOS：** 完整解压 macOS 通用 ZIP 后双击 `Start.command`。脚本根据本机架构选择 Apple Silicon 或 Intel 运行文件。若启动脚本缺少执行权限，在解压目录打开终端，执行 `chmod +x Start.command Stop.command` 后重试；脚本会设置对应二进制文件的执行权限。若系统提示未验证来源，先核对软件包与发布校验值，再按系统提示对相应文件允许打开；无需关闭系统安全功能。浏览器访问同一本地地址，双击 `Stop.command` 结束后台服务。

程序只监听本机回环地址。GUI 默认端口为 4317，实验链 RPC 为 8547。Windows 包面向 Windows 10/11 x64。按所附二进制文件声明的最低系统版本，Apple Silicon 需要 macOS 15.5 或以上，Intel 需要 macOS 13.5 或以上，Mac 启动脚本会检查。不要同时从多个软件包启动同一默认端口的程序。本次未在 macOS 实机完成启动测试，不能把 Windows 测试结果视为 macOS 实测结果；详细验证范围以发行包说明为准。

## 2. 首次准备环境

进入「链与环境」，点击「初始化环境」，或在首页点击「初始化本地环境」。启动完成后，右上角显示实验链已就绪。初始化会创建本地账户、实验代币 TokenA/TokenB、兑换池 AMM 与存款合约 Vault。

默认链 ID 为 31337。实验 Agent 初始持有 100 TokenA、0 TokenB，以及用于 gas 的测试 ETH；收款账户初始代币余额为 0。TokenA、TokenB 使用 6 位小数，界面任务中的 10 TokenA 对应最小单位整数 `10000000`。兑换池初始储备为 10,000 A 与 10,000 B，费率 0.30%；Vault 使用便于检查的 1:1 存款份额模型。

「恢复初始环境」回到平台标准基线。「保存当前快照」返回快照 ID；填入该 ID 并点击「恢复此快照」可在同一链进程内恢复。快照不跨重启保证有效，恢复后旧快照可能失效。连续实验可在显式恢复快照后从该状态新建运行；选择独立实验仍会恢复标准基线。

「停止链」关闭 Anvil，保留本地记录与 GUI 服务。关闭整个软件时先停止正在运行的实验，再运行 Windows 的 `stop.cmd` 或 Mac 的 `Stop.command`；关闭浏览器页面本身不会停止服务。

## 3. 运行第一批基线

进入「运行实验」，选择任务与「脚本基线」，点击「开始实验」。脚本基线按固定任务规则执行，在真实本地 Anvil 中构造、提交交易；它没有调用大模型，不可作为大模型能力实验数据。

| 任务 | 默认目标 | 独立检查重点 |
| --- | --- | --- |
| 查询余额 | 查询 Agent 的 TokenA 余额 | 真实查询记录、区块绑定、最终 JSON 答案一致，且未提交交易 |
| 转账 | 向 recipient 转账 10 TokenA | 发送方减少 10、接收方增加 10、目标合约与 calldata 正确 |
| 代币授权 | 对 AMM 设置 20 TokenA 授权 | 正确 spender、allowance 精确为 20、余额不变 |
| 兑换 | 用 10 TokenA 换取至少 9 TokenB | 授权、交易参数、池储备与恒定乘积计算一致 |
| 兑换后存入 | 将本次兑换所得全部 TokenB 存入 Vault | 本次新增 B 全部存入，保留原有 B，Vault 份额相应增加 |

V0.13 将本次任务目标保存为 `taskParameters`，供脚本基线、工具金额校验和独立检查器共同使用。默认值仍为上表。转账和授权使用 `amount`；两类兑换使用 `amountIn` 和 `minAmountOut`，都是人类可读十进制字符串，最多 6 位小数。金额须大于 0，最低输出可为 0。代币、recipient、AMM 与 Vault 仍由任务模板定义，本版没有开放任意协议或收款对象。

### 修改任务目标

在任务表单填写结构化金额，再点击「用参数重建任务输入」；也可修改「任务输入」，再点击「从任务输入解析目标」。界面显示本次核对目标和来源，开始实验前会重新核对。

例如，兑换输入写为「使用实验amm将30 TokenA兑换为TokenB，最少接受27 TokenB，收款人为agent。」或 `{"amountIn":"30","minAmountOut":"27"}`，核对结果应为 30 / 27，脚本、LLM 金额校验和检查器同时采用该目标。英文示例是 `Swap 30 TokenA to TokenB, at least 27 TokenB.`；转账示例为「向recipient转账0.5 TokenA」。如果文字不属于支持模板，请填写结构化参数。不要保留旧工具示例中的 10 / 9 后又写新目标 30 / 27。

同一字段出现多个不同目标、文字与结构化参数冲突、精度超限或无法识别必要字段时，平台明确报错，拒绝开始，不默默改回默认目标。结构化参数是声明目标，不能绕过可识别的文本冲突。平台不声称理解任意自然语言任务；添加新的代币、对象或任务语义仍需同步修改工具和检查器。旧记录没有 `taskParameters` 时按历史默认 10 / 20 / 9 复检，不以当前表单补写目标。

查询余额任务要求最终答案是严格 JSON 对象，不附加 Markdown 围栏或其他说明。四个字段都必须来自实际工具结果：`{"token":"A","address":"Agent完整地址","balanceBaseUnits":"整数最小单位余额","blockHash":"查询区块哈希"}`。例如将余额误写为格式化的 `100`，而真实最小单位应为 `100000000`，检查器会判定失败。

### 独立实验与连续实验

状态模式默认是「独立实验」，每轮从100 TokenA等标准初态开始。选择「连续实验」后不会重置当前链：默认目标转账一次，余额由100变为90；再连续转账，应由90变为80。切回独立实验，下次起点重新为100。本次目标来自核对后的任务参数；连续模式只改变起点，不暗中改变金额。

连续实验继承余额、allowance、池储备和Vault份额，允许余额不足或交易失败被真实记录。若存在待确认或排队交易，平台拒绝启动连续实验：请先出块并更新上一轮结论，或明确重置环境。每轮记录session_id、previous_run_id、实际起点区块与状态；初始化、重置或恢复快照后开始新的会话关联。

## 4. 连接 LLM Agent

切换到「LLM Agent」，填写支持工具调用的模型名称、OpenAI 兼容的 API Base URL、API Key、Temperature 与最多 Agent 步数。Base URL 通常以 `/v1` 结尾，平台调用 `/chat/completions`。可以连接支持该协议的云模型，也可连接本机模型服务；本机无鉴权服务可留空密钥。并非所有兼容端点都支持相同模型参数，请按服务文档选择模型。

在「工具、提示词与实验干预」中可修改系统提示词。留空使用默认值。任务输入会作为实际用户消息发送；平台另以系统消息提供本轮初态、模式与单位说明，完整保存在agent.context及实际模型请求中。工具白名单决定模型可见与允许调用的工具。本版按顺序执行工具调用，不并发提交交易。

### 金额单位与校验策略

工具的 `amount`、`amountIn` 和 `minAmountOut` 使用人类可读代币数量字符串。授权 20 TokenA 填 `"20"`，兑换输入 10 TokenA 填 `"10"`；不要预先乘 1000000。链上整数证据仍使用最小单位，例如 20 TokenA 等于 `20000000`。这些接口层级的单位不同，平台仅在链调用处转换一次。`get_state` 与初态消息同时提供明确的格式化代币数量，原整数证据字段保持不变。

默认金额校验策略为 `fixed_task`，名称为兼容旧记录保留，V0.13 实际检查的是本次已解析的 `taskParameters`，不再硬编码 10 / 20 / 9。不匹配时显示 `TOOL_AMOUNT_MISMATCH`，该请求不会签名、提交或触发合约调用；原参数和拒绝原因保留，Agent 可根据反馈发出新的正确调用。平台不自动将错误金额除以 1000000。若兑换后存入尚缺少本次新增 B 的实际证据，则返回 `TOOL_AMOUNT_EVIDENCE_REQUIRED`。

此校验约束本次模板目标金额，不是完整安全策略；账户、代币、spender及额外副作用仍由独立检查器判断。动态新增 B 取自本任务成功兑换的原始输出；续行时，可把原 pending 兑换哈希与刷新后成功交易绑定，采用已确认输出或同环境的新状态减原任务初态。工具返回替换改变 Agent 可见值，不改变实际证据。研究干预时，应记录是否启用 `fixed_task`。

在「工具、提示词与实验干预」中，金额校验默认勾选，对应 `fixed_task`；取消勾选进入 `schema_only`，只关闭目标金额匹配，字符串类型、格式和最多 6 位小数仍校验。独立检查器仍按本次声明目标判定。当前实验显示所用策略，旧记录标为未声明。`schema_only` 不会更改任务完成条件；数据分析应区分两种策略。

在合约调用详情中查看「金额换算（代币数量 → 合约最小单位，仅转换一次）」：`input` 是工具的人类可读数量，`baseUnits` 是实际 ABI 整数参数。借此可以区分模型传入错误单位与链工具转换结果；旧记录没有该字段时不自动补造。

密钥只用于当前页面与服务运行内存，不写入配置、数据集或浏览器本地存储。「清空」清除页面值；刷新页面后需重新输入。已发出的请求或正在执行的实验可能仍持有该次运行的内存副本。重新运行旧 LLM 实验时，应先在页面填写本次使用的密钥；旧记录不含可恢复的密钥。

接口实际提供的请求与响应会被记录，并进行敏感字段与已知秘密脱敏。不采集模型内部思维。Token 使用量按服务实际提供的信息保存；未提供或不完整时保留空值和原因，不以 0 代替。脚本基线的模型 Token 显示「不适用」。耗时、模型调用、工具调用、gas 与重试等指标可在完整检查结果中查看。

## 5. 暂停、干预与失败样例

运行前勾选「工具调用前暂停」或「交易提交前暂停」。到达控制点后，当前实验显示待执行名称和参数，点击「继续执行」前可检查内容。点击「取消运行」或「停止运行」发出取消请求；取消不会撤销已经广播的交易。

「工具返回替换 JSON」按工具名配置。例如 `{"get_balance":{"balance":"0","formatted":"0"}}` 会把相应工具的可见结果替换为给定对象。原始结果、可见结果与干预标记同时记录。替换工具结果不会撤销原始工具已经产生的链上效果；不完整的替换对象可能导致 Agent 或检查器失败，这是实验事实的一部分。

脚本模式的转账任务额外提供两种「转账实验干预」：

- **余额不足：** 将实际请求金额改为超过余额的金额，提交真实失败交易，用于检查回执与失败记录。
- **修改收款人：** 将实际收款人改为观察账户。交易可以执行成功，但任务检查器应判定目标失败。

正常转账、余额不足和错误收款人均应单独保存实验编号。干预前后的参数会记录为事件。失败样例用于检验采集与判定能力，不冒充模型自主行为。

## 6. 手动出块与分叉

在「链与环境」关闭「自动出块」，再运行转账基线，可以获得交易已提交但尚未确认的样例。等待运行结束后，填写区块数量和推进秒数，点击「手动出块」。「推进时间」指每个新块相对前一块的间隔，不是所有块合计。例如 3 块 × 12 秒，实际总时间差应为 36 秒。范围为 1–1000 块、每块 1–86400 秒，界面展示前后区块、时间戳和实际差值。实际链上时间不等于模型调用耗时。

随后回到实验，点击「更新链上结论（仅检查器）」读取新链状态与回执。该操作不调用模型，也不会让已经结束的 Agent 自动看到新状态。仅手动出块和更新结论不能作为 Agent 已经继续决策的证据。

「独立检查」只重新评价已保存的证据，不查询新的链状态。因此，刚手动出块后，应使用「更新链上结论」而非期待离线检查改变旧证据。更新结论要求仍处于该实验对应的链环境，且没有后续实验占用该状态区间；否则请使用离线复检。新版结论作为派生记录保存，原始事件不会被覆盖。结果区会标明证据来源与检查时间：离线复检始终使用原始运行快照，因此原始pending经链上追认成功后，再做离线复检仍可能显示pending；此前的追认结论保留在derived历史文件中。

如需分叉，在初始化前展开「主网分叉」，填写可读取历史状态的 RPC URL 和固定区块号。第一版仍在分叉之上部署本地实验合约；它没有自动接入真实 Uniswap/Aave 等协议，也不模拟真实网络的完整竞争行为。研究真实协议时需要增加相应工具、任务及检查器。分叉的可重现性还依赖上游历史 RPC 可用性；导出包不会把整条主网历史状态下载到本机。

## 7. 看懂轨迹和判定

「当前实验」显示唯一 RUN ID、执行模式、状态及主要成本。行为轨迹按事件顺序排列，可搜索事件类型、工具名或交易哈希，点击事件查看完整 JSON 与原始文件引用。「跟随最新」控制是否自动滚动到最新记录。

| 状态 | 含义 | 常见后续操作 |
| --- | --- | --- |
| 成功 | 证据满足任务条件 | 保存轨迹并核对完整性 |
| 失败 | 有证据证明目标未达成或违反条件 | 查看失败断言、参数和回执 |
| 等待确认 | 已知交易尚未确认 | 手动出块，再更新链上结论 |
| 结果未知 | 必要证据不可得，不能断言成功 | 查看缺失证据或 RPC 错误 |

独立检查器不把 Agent 所说的“成功”当作成功证据。余额查询任务还要求最终结构化答案与真实观测匹配，避免“没有提交交易”被误判为“查询已完成”。初始条件错误、数据损坏或证据缺失要单独看待，不能统计为正常成功实验。Agent 运行异常与链上任务结果也可能不同：例如模型最终回复异常，但已提交交易确实完成目标。

### 失败定位与链上状态对比

结果区分开显示交易执行与任务判定。交易成功只表示链上调用未回滚，不保证收款方、授权对象或金额符合任务。中文诊断列出失败环节、检查名称、期望值、实际值和建议；有对应证据时可定位到轨迹事件。英文检查ID仍保留。

状态变化表直接展示余额、allowance、池储备、Vault资产和份额的前值、后值、变化量与证据区块。代币等使用6位精度，同时保留最小单位整数；测试ETH使用18位精度。90 TokenA对应90000000，而900000最小单位是0.9 TokenA。金额使用整数计算，缺失证据显示未知，不填0。

余额查询失败时先看最终 JSON 账户、余额最小单位和区块哈希；授权失败时核对 TokenA 的 spender 是否为 AMM、最终额度是否等于本次 `amount`。例如默认目标 20，而实际 20000000 TokenA，链上成功仍应任务失败。自定义任务应先核对 `taskParameters`、目标来源与参数换算记录。

授权余量检查按实际成功交易的 nonce 顺序计算：初态额度遇到成功 `approve` 后被新额度覆盖，再减去其后的兑换或存入消耗。例如初态 20、当轮重新授权 10、兑换消耗 10，最终应为 0；如果没有重新授权则应为 10。若当轮误授权很大金额，检查器仍按实际额度核对余量，但会单独报告授权范围或交易归属不符合任务，不通过错误的算术结果掩盖超额授权。对应兑换或存入之前的合规重复授权允许执行。

## 8. 回放、重新运行与导出

进入「实验档案」，点击「轨迹回放」读取已保存记录。回放不重新调用模型、不提交交易；即使停止实验链，仍可回放。这里的离线指不依赖模型和链，GUI 的本地服务仍需启动。

「恢复初始状态并重新运行」使用原实验配置创建新的 RUN ID，并保存父实验编号；当前实现恢复平台标准初始基线，且校验构建源码哈希与初始区块哈希。若版本或环境不一致，软件拒绝把该次执行标记为原配置重跑，应切回原版本及环境或另建实验。运行开始会重置链，请先完成所有待确认交易的观察。分叉实验要求先初始化相同的分叉环境。重新调用 LLM 可能得到不同输出；不要以轨迹逐字相等作为模型实验可复现的必要条件。

上述自动重跑仅适用于独立实验。连续实验可离线回放和复检；本版不支持跨会话自动恢复任意历史连续起点，也不会重置到100后冒充原样重跑。若需从相同连续起点再执行，请在首次运行前保存本会话快照，之后显式恢复该快照，再新建连续实验。导出的当前Anvil状态用于保留起点证据，不承诺完整公共主网状态可移植恢复。

「导出实验包」下载一个自包含 JSON 文件，包含配置、原始事件流、内容寻址文件、清单和派生检查结果。未封存或完整性校验失败的记录不可作为完整实验包导出。在档案中点击「打开导出包」可从磁盘选择文件，浏览器在本地校验原始文件哈希、字节数和事件引用后显示轨迹，不上传文件。派生标签不属于原始文件清单，文件哈希也不证明来源真实性。

离线查看图时，先启动本地 GUI 服务，无需初始化 Anvil 或填写模型密钥；进入「实验档案」→「打开导出包」，选择完整实验 JSON。在「工具与合约执行轨迹」展开工具查看详情，点击「溯源关系图」节点查看属性、关联边和来源事件，再使用「导出图 JSON」或「导出 GraphML」。旧包缺少的关联会显示为缺失，不自动补造。单独的图 JSON 用于图分析工具，不能代替完整实验包导入回放。

## 9. 文件结构、备份与命令行

日常数据保存在软件目录下的 `data` 文件夹，路径也可在服务状态中查看。至少备份整个 `data`，不要只复制 `events.jsonl`。

```text
data/
  runs/<run_id>/
    config.json           # 固定配置、任务、版本与环境
    events.jsonl          # 顺序事件与内容引用
    blobs/<sha256>.json   # 实际负载：交互、交易、状态等
    manifest.json         # 封存清单、哈希与字节数
  derived/<run_id>/
    <时间戳>.json          # 版本化的后续检查
    latest.json           # 最近检查结果
  environment/            # 环境相关文件
```

原始记录与后续标签分离。不要手工改写 `runs` 中的文件；分析时新建派生文件或复制数据。源码包包含固定依赖锁文件、构建脚本和命令行入口，适合进一步开发和批量实验。命令行具体参数以 `README` 与 CLI 帮助为准；GUI 是无需编写代码的常规入口。

## 10. 升级与旧数据

升级到 V0.13 时先正常停止旧程序并备份整个 data。新包解压到新目录，保留旧目录。旧实验可通过导出包离线查看；需要档案列表时，在两版均停止后复制整个旧 data，并保留原副本。旧原始文件和标签不自动重写；新版复检追加 checker 2.2.0 判定。缺少任务参数的历史记录仍用历史默认目标，不把旧自然语言输入事后重新解释为新目标；缺少模型版本或图关系的字段显示未记录。旧软件包用于原版本重跑，新版不会绕过源码哈希检查。

新建运行记录 `taskSpec`、`taskParameters`、`taskParameterSource` 和 6 位代币精度；续行额外保存父清单哈希、模型历史来源、出块结果、继承交易及原始事件引用。历史超额授权不会自动撤销；需要干净起点时明确选择独立实验或恢复环境。

## 11. 常见问题与使用边界

- **浏览器无法连接：** 确认完整解压、已运行启动脚本、地址为 `http://127.0.0.1:4317`，并检查 `data/server.stderr.log` 与端口占用。
- **环境无法初始化：** 查看界面报错、Anvil 路径、系统架构、可执行权限和端口错误；分叉还需核对固定区块及 RPC 访问能力。
- **模型认证或格式错误：** 检查 Base URL、模型名称、Key 和工具调用支持。接口报错会进入记录，不自动伪造成模型输出。
- **任务失败：** 先检查核对后的本次任务参数、输入和目标来源，再查看工具白名单、替换结果、干预及链上断言。
- **停止后仍有交易：** 广播与确认是两个阶段，取消 Agent 不会取消已进入交易池的交易。
- **数据无法导出：** 先等待运行结束；若报告哈希不一致、缺失文件或未封存，应保留原文件用于故障分析，不手工修改清单让其通过。

该版本是单机、单 Agent、顺序实验平台；它不提供多租户服务、批量并发调度或桌面自动更新。实验账户与测试资产仅用于本地研究，不导入个人私钥、生产 API 权限或真实资产。框架和模拟协议的具体改造入口见源码与选型说明。


## 12. 执行轨迹与通用溯源图

当前发行标识为 V0.13，程序 0.1.3，修订 beta-1，检查器 2.2.0。每轮结束后在「工具与合约执行轨迹」查看参数、原始与 Agent 可见结果、合约函数、回执和 EVM 内部调用。完整实验包包含图 JSON、GraphML、节点与关系 CSV、详细轨迹等派生文件；原始记录与派生图分开保存，缺失信息不补造，具体格式见[执行轨迹与溯源图说明](trace-schema.md)。

图的关系类型复选框同时作为颜色图例。可选「全部关系」「清空关系」「只看 follows_run」，也可单独勾选 `invokes` 等当前数据中实际存在的类型。点击连线高亮该关系及两端节点，点击节点高亮相邻关系；详情包含属性和原始事件入口。「清除高亮」回到普通视图。`follows_run` 只表示运行先后，不代表业务因果。

使用加减按钮缩放、拖动平移、「适应宽度」「展开大视图」查看大图；按 Esc 关闭大视图。大图默认折叠部分节点，界面显示可见数与总数，点击「展开更多节点」逐步显示。图 JSON 和 GraphML 下载始终保留完整图，不受类型筛选、预览折叠或当前缩放影响。离线导入完整实验包后同样可以筛选、高亮和下载图。

GraphML 和 JSON 是通用有向多重图。边以实际调用ID、交易哈希和callTracer父子关系为依据；连续运行的先后顺序不等同于因果关系。离线导入图属于派生视图，不代表原始清单认证了图的结论。导出时校验原始证据并重新生成，准备、提交未知、已广播和确认的状态分别保留。

## 13. 档案筛选与模型记录

「实验档案」提供独立的任务、任务完成结果和链上执行结果下拉框；搜索支持中文任务名称、英文任务 ID、RUN ID、模型名称和任务输入。多个条件同时生效，刷新档案保留选择；点击「清空筛选」恢复全部。

任务完成结果来自独立检查器，分成功、失败、等待确认、未知。链上执行结果分交易成功、回滚/失败、等待确认、结果不一致、未知、未提交交易。纯查询单独显示查询行为，并可在未提交交易范围查看；交易成功、任务失败是有效组合。例如错误收款人交易成功，但任务不合格；查询任务成功也不要求存在交易。

每行的「模型版本」分别显示请求模型名与接口响应实际提供的 `model` 字段。前者可能是服务别名，后者也仅是服务自报，不能证明底层权重或提供者路由没有变化。接口没提供时显示「未提供 / 未记录」，脚本基线显示无模型。点「输入与配置」直接查看这次实际任务文字和保存的脱敏配置，无需先进入轨迹；旧数据缺失字段不使用当前表单补写。

## 14. 出块并继续 Agent

该功能适用于当前环境中最后一次已结束、完整封存、尚未成功的 LLM 运行。保持原链环境和 epoch，先在「链与环境」填写出块数量及每块秒数，必要时重新填写模型 API Key，再点击当前实验的「出块并继续 Agent」。该按钮可能再次调用模型并提交新交易，请把它作为一次新的关联采集运行。

平台先按设定出块，读取最新链状态并核验此前交易，再从原始模型请求、响应和工具结果恢复闭合的服务可见消息历史。在历史之后追加明确标记为平台观察的 user 消息，包含最新状态与确认信息；不会伪造旧工具返回或模型输出，不重启一份全新的任务提示。原父任务的初态、目标、模型与工具配置保持，只有出块参数和重新填写的密钥可变。

续行产生新的 RUN ID，并记录父实验 ID、父清单哈希、历史消息与事件来源、出块结果、继承交易和新增行为。父原始 pending 记录保持不变。子运行以原任务初态累计评价已发生交易；同一哈希去重。多次续行仍保留原任务起点，不把已经兑换的部分当作新任务重新兑换。Agent 根据实际历史和新状态自行决定等待、查询或完成后续存入，模型可能犯错，独立检查器仍负责最终判定。

续行成本分开标记：`transaction_scope=cumulative_task` 表示子运行 gas 与 transaction_attempts 累计原任务交易；`model_scope=current_run` 表示模型调用与 token 只计本子运行。统计父子总成本时不要直接把各轮 gas 相加，应按交易哈希去重或采用最终子运行的累计交易值；模型调用与 token 则按各轮实际记录分别汇总。

若记录损坏、最后一次交互不完整、工具调用缺失唯一结果、链被重置、已有后续运行、任务已成功、运行中或只导入了离线包，平台拒绝续行并显示原因。脚本基线不支持该按钮。取消不会撤销已广播交易。此机制采集接口实际提供的历史与续行行为，不采集模型内部思维，也不承诺提供者内部会话状态可恢复。
