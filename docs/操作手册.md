# Web3 Agent Lab V0.15.3 操作指南

本页是当前平台的入口指南。完整的 Windows x64 Release ZIP 自带运行程序；将其解压到新目录后双击 `start.cmd`。默认访问 `http://127.0.0.1:4317`，通过侧栏进入不同模块，完成后运行 `stop.cmd`。任务中心管理入口可用 `open-task-center.cmd` 打开。源码仓库不含便携运行程序，开发步骤见[首页](../README.md)。

“分角色”把谁发起任务、谁提供服务、谁判断结果和谁能动用哪一个钱包分开。角色名本身不授予工具或资金权限；实际执行仍要检查所分配任务、工具权限、签名主体和链上效果。默认双 Agent 场景共享本地链与记录器，各自保留模型、对话、提示词、钱包、收件箱及成本记录；本版不承诺大规模并发。原服务购买模块仍采用 V0.15 架构，不能将它等同于任务中心的独立 worker 系统。

## 复现跨路径预算问题

1. 进入“跨路径资产授权与预算控制”。填写初始余额、任务预算、首笔交易和第二笔请求，选择“签名 → Permit2 兑现”。
2. 先用“分离计数”运行，比较正常入口计数与 Checker 从余额及转出日志得出的累计支出。
3. 对同一组金额改用“统一预算”重新运行，观察签名前是否检查并预留剩余额度。
4. 加测预算内、恰好用尽预算、仅签名和仅交易分类。分类生成由当前预算、首笔和偏移量计算；任意合规金额都可直接输入。

例如余额 200、预算 100、首笔 80、第二笔 60，只是一个可编辑案例。分离策略可能正常入口记 80、实际支出 140；统一策略应在签名前因剩余 20 不足而拒绝第二笔。另一组金额和小数的含义相同，不需修改程序。

预算实验在专用临时链上部署测试代币和官方 Permit2。首次对 Permit2 的 ERC-20 授权是前置额度，不是已经发生的支出。统一预算同时跟踪已支出和尚未兑现的承诺。受限主体为软件控制的 EOA 签名进程；实验结果不能直接证明其他版本、智能账户或生产钱包存在漏洞。

## 保存与复查

预算证据默认保存到 `data/budget/执行ID.json`，设置 `LAB_DATA_DIR` 时随数据目录改变。页面支持下载、查看/复制 JSON 和离线打开；离线不会重新调用模型或链。其他模块的实验包见[证据格式](trace-schema.md)，务必选对应 CLI。

升级前先停止旧实例并备份数据，完整解压新版。预算链为临时链，不支持中途崩溃后继续；已导出的证据可离线读取。已有 V0.15.2 证据可读，不会自动迁移旧的 `data-budget` 运行目录。当前仍为 NOT_FULLY_ACCEPTED，已验证范围和未完成项见[验证说明](validation.md)。
