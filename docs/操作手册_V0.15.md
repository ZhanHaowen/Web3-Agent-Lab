# V0.15 操作手册

## 1 本版购买的是什么

本版提供 service_purchase 场景，结算方式固定为 service_escrow。Buyer 支付 TokenB，Provider 查询指定实验代币及账户在固定区块的余额，交付 balance-report-v1 JSON。Evaluator 重新查询该区块，按确定性规则判断是否付款。事后 Checker 再独立读取固定区块和结算状态，分别检查内容质量与资金。

实验使用本地 Anvil Chain 31337。支持 TokenA 或 TokenB，账户可选 Buyer、Provider 或 Recipient；本轮区块在场景初始化结束后固定，界面右侧 request 中展示 blockNumber、blockHash、token、account。暂未开放任意合约、任意账户或任意历史区块输入。用户不需要手动寻找完整地址。

Evaluator 是信任主体。它错误批准可能支付错误产物，离线或错误拒绝可能使已工作的 Provider 收不到款。平台通过实验暴露这些后果，不宣称无信任公平交换。

## 2 安装与正常实验

关闭旧版本服务，将 ZIP 完整解压到新目录，运行 start.cmd。打开首页的“购买 Agent 服务”链接，先初始化实验链。

默认配置为脚本基线、支付5 B、Buyer最高预算5 B、Provider最低价格5 B、有效期600链上秒、正确报告、诚实验收。点击开始实验后，按钮立即变深并显示加载文字；运行中耗时持续增长，结果确定后冻结。左侧配置不挤占右侧结果区。

正常步骤：Buyer询价 → Provider报价 → Buyer接受真实quoteId → Buyer精确授权TokenB → 创建任务 → 按expectedBudget出资 → Provider检查任务 → 生成固定区块报告 → 提交报告哈希及交付内容 → Evaluator重新查询并验收 → 合约付款 → Checker复查。

| 对象 | 初始 A | 最终 A | 初始 B | 最终 B |
|---|---:|---:|---:|---:|
| Buyer | 0 | 0 | 100 | 95 |
| Provider | 100 | 100 | 0 | 5 |
| Evaluator | 0 | 0 | 0 | 0 |
| Escrow | 0 | 0 | 0 | 0 |

代币6位精度，界面输入人类单位，链上使用整数。ETH仅用于Gas。读取余额报告本身不发资金交易；支付使用独立服务托管。

## 3 模型模式

选择“双 LLM Agent”，分别填写Buyer和Provider的兼容工具调用端点、模型与Key。允许相同API与Key，双方消息历史、私有目标和钱包分离；可能共享供应商额度。Evaluator无需API。

Buyer依据自己的预算决定是否接受，Provider依据最低价格报价或拒绝。首版价格必须等于配置的支付价格，暂不支持自由价格发现。实际工具结果和阶段进度会反馈给模型，文字声称“已接受”不会当作工具执行。模型不可指定签名者、任意收款地址或修改链上预算；提交工具无任意交易参数。

模型供应商输出仍可能超时、触发额度或用尽调用预算。本次自动验收使用明确标记的本地模型协议夹具，未对云端glm-4-flash做真实调用测试。

## 4 故障实验

| 实验 | Provider交付 | Evaluator | 预期结果 | 应观察到 |
|---|---|---|---|---|
| 正常购买 | 正确报告 | 诚实 | 正确交付并付款 | Buyer95 B、Provider5 B、产物passed |
| 错误产物 | 错误余额/区块/格式/哈希 | 诚实 | 拒绝产物并退款 | Buyer恢复100 B、Provider0 B、产物failed |
| 错误批准 | 错误余额 | 错误批准 | 检测错误付款 | 已付款但产物不合格；Checker必须失败 |
| 错误拒绝 | 正确报告 | 错误拒绝 | 拒绝产物并退款 | 产物passed但Provider未获款，显示信任风险 |
| 验收离线 | 正确报告 | 离线 | 超时退款 | 暂停于Submitted，链上到期后手动退款 |
| 不交付 | 不交付 | 诚实 | 超时退款 | 暂停于Funded，到期后退款 |
| 买方拒绝 | 正确报告，预算小于价格 | 诚实 | 拒绝购买并不出资 | 无交易，无托管扣款 |

“预期结果”只影响实验检查目标，不会伪造付款或掩盖错误产物。即使预期设为检测错误付款，质量失败仍显示检查未通过。

## 5 超时与停止

有效期按区块时间计算，不按屏幕耗时计算。离线或不交付实验会自动暂停供观察。可把每块间隔秒数设置为大于有效期的值，点击“出块并对账”，然后点击“超时退款”。到期本身不自动发退款交易。未到期退款会被合约拒绝。

停止决策不会撤销已广播交易，也不会自动退还已托管资金。同一服务进程、同一链且没有其他活动实验时，停止后的Funded/Submitted任务可继续手动出块与退款。若重置链或启动新的独立实验，旧任务的合约状态可能已被替换，网关会拒绝旧场景签名；因此应先完成待确认交易和退款，再重置。

手动出块模式下，Pending/Unknown会阻止新实验重置链。先点击出块并对账，确认原交易；不能换nonce或新建订单重复支付。全局暂停、角色暂停、单步与交易前暂停沿用已有控制。档案回放只读，跨进程任意检查点续跑未实现。

## 6 看懂右侧结果

结果分别展示结算状态、业务结果、Buyer和Provider目标、内容质量及完整性。Job状态：0不存在、1Created、2Funded、3Submitted、4Completed、5Rejected、6Refunded、7Cancelled。取消只适用于未出资任务；出资后应由验收拒绝或到期退款处理。

报告包含schema、chainId、blockNumber、blockHash、token、account、balance最小单位整数、decimals。内容哈希匹配只证明字节一致；内容正确性还需与固定区块独立读取结果比对。Evaluator验收及其故障模式、Checker质量断言均可查看。

交易记录展示actor、合约方法、nonce、哈希、回执和可获得的EVM trace。图新增service_job、artifact及验收关联，关系来自显式事件引用，不补造推理链。

## 7 导出与离线检查

点击导出完整场景包；包内包含scenario、原始事件、内容寻址负载、ABI与代码哈希、初末状态、图、GraphML、CSV、执行轨迹、labels/checker-service-1.0.json和哈希清单。场景档案只读查看或从共同初态创建新episode重跑。旧Key不会从脱敏档案恢复，需要重新填写。

在解压目录命令行运行：

```text
runtime\node.exe scripts\peer-offline.mjs verify examples\service-v015\01-correct-paid.json
runtime\node.exe scripts\peer-offline.mjs check examples\service-v015\01-correct-paid.json
runtime\node.exe scripts\peer-offline.mjs check examples\service-v015\03-wrong-approval.json
```

最后一条应给出失败且退出码2，因为已支付错误产物。verify只验证内部哈希与事件顺序，不认证采集者。离线check使用记录中的链读取证据，不联网、不执行包内程序、不签交易。浏览器离线打开只做哈希校验与记录回放；新计算结果应使用命令行check。

## 8 当前边界

本版Windows x64，本地固定代币和固定角色，不是生产市场。不支持服务手续费、hook、部分交付、仲裁、任意Provider注册、外部A2A、x402 facilitator、AP2或ERC8004。合约以原方案的本地托管profile为设计参考，不声称ERC8183完整兼容。

同进程逻辑隔离不等于敌对代码沙箱。原单Agent发布bundle与旧实验读取入口保留；原缺失的TypeScript源码未补造。旧数据应自行备份，不做隐式迁移。
