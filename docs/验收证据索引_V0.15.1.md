# V0.15.1 验收证据阅读说明

本发行标签为规范修订预览版，状态为 **NOT_FULLY_ACCEPTED**。本说明用于识别证据边界，不替代 AT-01 至 AT-36 的逐项报告，也不将历史通过结果提升为本次全通过。

## 先核对构建，再阅读状态

每次运行验收脚本都会在报告中记录 `buildHash`。应将它与交付的 `build-info.json.sourceHash` 比较，并核对同目录 `machine-info.json`、CSV、执行 ID 及证据文件。不同构建之间的 PASS 不能直接累加成最终通过；修复后应在新构建复测。若源码或构建配置在测试后又变更，旧结果仍是该旧构建的证据。

`--case` 只执行一个用例，其他项目默认 BLOCKED。core 不涵盖所有必测条件。脚本中的一个 PASS 也只说明该脚本实际断言通过；若标准要求更多子条件、实机、截图或独立人员，应继续保留缺口。

## 最终复测目录

最终修补后的 r3 报告已生成，汇总见 [最终验证摘要](最终验证摘要_V0.15.1.md) 和 `v0151-final-acceptance.json`。引用单项证据时仍需核对其 buildHash 与交付构建一致；不同目录的未测项不能自动合并为通过。

| 目录 | 复核范围 |
|---|---|
| `docs/acceptance-final-core-r3/` | 最终核心用例、逐项汇总与实际缺口。 |
| `docs/acceptance-final-recovery-r3/` | 最终恢复用例及 supplement 补充证据，重点核对正常关闭、原链再连接、暂停门与清退。 |
| `docs/acceptance-final-stability-r3/` | 最终稳定性测量，核对实际任务数、状态延迟及资源记录。 |

交付的最终验证摘要应明确引用实际生成的各报告、单元测试、旧功能与服务回归。核心、恢复和稳定性不互相替代，也不因名称含 final 就自动通过。早期 `acceptance-final-*`、`*-r2/` 与其 supplement 均保留各自构建边界；core-r2 未出现 FAIL，不表示全 36 项或所有子条件通过。

## 必须保留的未完成范围

- 完整运行时 TypeScript 迁移、冻结依赖安装和第三方干净全源码构建，不能由严格接口类型检查替代。
- 未执行的恢复条目，包括 Agent 多个崩溃点、归档/ACK 两个崩溃点及链身份/写入失败注入，不能由 AT-21 一项重测替代。
- AT-32 需要真实模型凭据及 10 次完整尝试；请求协议夹具和本地模拟服务不算真实尝试。
- AT-31、AT-34 的 GUI 验收因 ComputerUse 无法可靠识别和确认 URL，当前明确为 BLOCKED；静态 DOM、API 或旧版截图不能代替本轮浏览器交互和双尺寸实测。
- AT-35 需要 Apple Silicon macOS 原生包及实机证据；本次 Windows 包不满足该条件。
- AT-36 需要独立人工核验与签字，自动化不能代签。

其余任务注册、身份对抗、消息重复、余额/授权连续状态、隐藏额外交易、离线篡改、隐私、GUI 和稳定性子条件，按报告实际覆盖逐项判断。没有测量就不写已通过。发布清单中的 NOT_FULLY_ACCEPTED 用于保留这一交付边界。
