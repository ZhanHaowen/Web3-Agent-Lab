# V0.17.0 Research Beta 操作与实现说明

本次发布为 **V0.17.0 Research Beta**（package：`0.17.0-beta.1`），在 V0.16.0 基础上增加采购与支付轨迹研究模块。Windows x64 已实测；Mac 入口保留但尚未真机验证。全部链上资产均为本地测试资产。更新总览见[发布说明](V0.17.0-RELEASE-NOTES.md)，回归范围及失败记录见[测试报告](V0.17.0-TEST-REPORT.md)。

原单 Agent 五类任务、任务与 Agent 中心、双 Agent 换币、分角色服务购买、跨路径预算以及本地/API 模型入口均保留。新增研究每次运行使用自己的临时链和数据目录；已执行的 Windows 回归未发现原核心功能退化。这不等于旧数据库迁移、所有真实模型组合、原功能所有高级控制及 Mac 均已全面复验。请将新包解压到新目录，保留旧包及数据备份。

新增的有意限制是：研究实验运行期间不能切换或停止共享本地模型，避免改变采集中途的运行条件。多个模块使用同一推理服务仍会竞争计算资源，本版不承诺性能完全不受影响。

## 1. 启动与首次实验

解压便携包到短目录（如 `C:\Web3Lab`），双击 `open-research.cmd`。默认页面为 `http://127.0.0.1:4317/research.html`。便携包含 Node、Anvil、预编译依赖，不需要安装 node_modules；Qwen 模型权重不包含在包内。

如果已有其他版本占用端口，使用其自身停止入口，或在 PowerShell 中设置 `$env:LAB_PORT='4373'` 后启动新包。不要覆盖旧包或复制旧运行数据库到新包。原有单 Agent、多 Agent、服务购买、预算控制和本地模型页面仍可使用。

首次推荐：x402 exact、规则策略“按服务反馈调整”、难度 3、种子 42、私有预算 `150000`、初始余额 `1000000`、最多 12 步。点击运行，待实验封存后查看采购、链上检查和任务结果，再分别下载公开包与私有完整包。6 位代币精度，`10000` 最小单位等于 `0.01` Token；这里填写最小单位，不是旧单 Agent 工具的可读数量。完整平台使用 `stop.cmd` 停止。

切换“真实模型调用”时，可沿用本地模型页面配置的 Qwen3 4B，或使用支持工具调用的兼容 API。密钥仅在本机输入，不写入实验配置文件。模型请求明确 `tool_choice:required`、`parallel_tool_calls:false`，每一步应调用 `purchase_service` 或 `finish_task`。不支持这些参数的后端会明确失败，不会偷偷回退为规则策略。

## 2. 可运行的六种部署

- `x402-exact`：官方 SDK 的 HTTP 402、EIP-3009 授权、验证与真实 ERC-20 结算。
- `x402-batch`：官方 batch-settlement、voucher、通道注资、累计结算与未使用本金退款。已消费服务的费用不因退回本金而消失。
- `ap2-x402-exact`、`ap2-x402-batch`：本地 ES256 签名 mandate 子集叠加 x402。核验签发方、金额、收款方、资源、链、代币、过期、重放与累计额度。采用整数分约定，不支持分以下金额；不是完整 AP2/SD-JWT 生态认证。
- `mpp-evm-charge`：官方 mppx `WWW-Authenticate: Payment`、凭证与回执，通过本地 settler 提交真实 EIP-3009 转账。未实现 Tempo session、Stripe、外部商户和 MCP 扩展。
- `erc8183-core`：本地客户/服务商/评估者托管合约，包含交付、确认、拒绝和到期退款。未实现 hooks、费用、ERC-2771，也不等于 Virtuals ACP SDK 互操作。

协议能力清单同时列出 L402、UCP、OpenAI/Stripe ACP、Visa TAP、Mastercard Agent Pay、Nevermined、KYAPay、Virtuals ACP。它们尚未适配，不出现在可执行配置中。账户抽象、身份注册、MCP/A2A 与支付结算分层记录，不把这些名称互相替代。

测试 token 允许实验性 mint。batch 的 SDK 标准地址通过 Anvil setCode 装载官方合约运行时代码，部署来源和哈希写入 manifest；这不是生产 CREATE2 部署承诺。不要将测试合约部署为真实资产协议。

## 3. 采购环境与私有真值

三类任务为证据综述、风险分析、趋势分析。所有任务共享发现、分析、核验能力的 lite/pro 六个服务；固定价格 `10000/30000`，不以任务标签编码价格。任务内容来自可复现构造语料。模型/规则策略实际接收 HTTP 返回后选择下一步，不用预写支付轨迹替代交互。

私有预算与公开初始余额独立设置；策略为成本优先、质量优先、自适应。脚本的成本策略优先低价服务，质量策略优先完整覆盖，自适应策略按实际返回覆盖率追加或升级采购。真实模型接收同样的私有任务、策略和预算以及实际服务返回，自行决定下一步；保留指定策略与实际决策，尚不自动判定模型是否遵循策略。低价服务可能覆盖不足，质量优先与自适应也受预算约束，因此失败是合法实验结果。任务检查与付款检查独立：付款成功不等于服务已交付，也不等于任务成功。

私有账本按“已结算 + 预留 − 已确认退款”计算占用和剩余额度。仅服务请求失败不会恢复预算；batch 未消费通道本金返还与已购买服务的成本分开记账。这里的预算是真实授权限制，不把公开钱包余额直接作为隐藏预算标签。

GUI 可干预第一笔服务的质量或付款后交付。CLI 配置 `workload.faults:[{purchaseIndex:0,kind:'withheld'|'low_quality'|'http_failure'}]`；ERC-8183 另支持 `timeout`。取消不会伪造已付款交易回滚。

背景交易为同 token、同商户、相同价格档位的真实转账；单独种子生成，使用账户 8。每次采购前插入 1 或 3 笔是顺序交错，不是并发多任务；公开账户身份仍可筛选，不能视为匿名化。

## 4. 文件与攻击者边界

GUI 数据在 `data/research/runs/<runId>/`；若设置 LAB_DATA_DIR，则位于该目录下的 `research/runs/`。

- `config.json`、`manifest.json`：任务配置、模型标识、调用策略、代码身份、协议版本、初态与部署参数。
- `raw/events.jsonl`、`raw/blobs/`：追加原始事件和内容寻址载荷，包括真实模型请求/响应、工具及支付证据。本地模型另捕获运行 manifest、props、日志等原生资料；不可获得的可选项明确标记，必需资料缺失会使 recordingComplete 为 false。
- `private/ground-truth.json`：任务、私有预算、策略与实际检查结果；预算台账、采购/交易关联和支付证据也只供研究者。
- `observer/observer.json`：从 RPC 区块、交易、calldata、回执、日志独立采集的公开数据；不是从私有日志删字段生成。
- `observer/graph.json`、`graph.graphml`、`nodes.csv`、`edges.csv`：公开图；不添加不可见的任务边。
- `derived/`：研究者的私有溯源图，引用原始事件，缺失关系明确标记，不与公开图混合。
- `checker.json`、`summary.json`、`integrity.json`：检查结果、成本状态与封存哈希。

公开观察采用区块时间，不使用内部毫秒时钟。广播者与经济付款者分开；保留链上本来公开的 calldata、日志和已消费签名痕迹。不向攻击者提供任务提示、真实隐藏预算、工具返回、请求关联或模型消息。

私钥、助记词、API Key、可复用签名/JWT 仅保存脱敏描述或哈希。原始记录不等于恢复凭证的档案。研究者完整包含实验私有真值，只用于内部核验；对外攻击输入应单独使用公开包。

## 5. GUI 导出与离线回放

选中已结束实验，可分别下载攻击者视图与私有完整包。公开导出按白名单从 observer 重新生成，拒绝符号链接，不采用可能夹带私有资料的预计算文件。

“离线攻击者视图”页加载公开 JSON 后显示图和节点列表，点击节点查看字段与直接关系。该页不连接模型、RPC 或实验 API；拒绝私有完整包。布局图展示前 100 个节点，列表和下载保留全部节点。

轨迹回放不重新调用模型，也不再付款。重新运行需要新目录和新 runId，重建同配置初态；模型输出、随机签名、链时间与交易哈希可能不同。不能声称整个运行逐字节可复现。

## 6. 推断与评价

本版围绕四项研究能力形成独立流程：

1. **可观察轨迹**：从 RPC 重新采集公开交易、实际日志和区块时间，保留公开 JSON 与图，和研究者原始记录、真值、私有因果关系分开。公开广播者与付款者不混同。
2. **任务推断**：目标标签为证据综述、风险分析、趋势分析三类任务；共享服务与价格，不人为用独有商户或价格编码任务。最近质心分类器输出混淆矩阵、Macro-F1、准确率、接受覆盖率和拒识结果。任务类别是否具有可泛化信号仍需实验验证。
3. **隐藏预算推断**：目标是私有**总授权上限**，采用 kNN 邻居中位数与验证集误差校准区间；报告 MAE、经验覆盖率、区间宽度及常数中位数基线。账本保留每步剩余预算，但当前攻击器尚不估计剩余预算曲线或子 Agent 分配。
4. **采购策略推断**：目标为配置的成本/质量/自适应标签，分类与拒识方式同任务推断；可以比较规则与真实模型轨迹。LLM 的标签是给定策略，不是已证明其实际遵循的真实策略，不能将分类结果称为恢复模型思考过程。

GUI 勾选至少 5 份不同实例执行评估；5 份只是入口下限，不是统计有效样本量。尽量覆盖多任务、策略、预算和种子，同时保留失败、未知及未完成实验。当前 GUI 默认按实例切分；代码接口 `makeDataset` 还支持模板、模型和指定组切分。重复观察、克隆及共享实例合并后不能跨集合泄漏。模型分组采用权重哈希或服务商/模型身份，seed、温度或端口变化不算新模型。

攻击特征目前是交易/付款次数、商户频次、分资产金额合计、相邻商户转移、秒级付款跨度/间隔和同块次数。`extractPublicFeatures` 提供金额、顺序、时间、商户及钱包开关，供代码级消融；当前不是 Transformer 序列攻击或图神经网络，图数据导出不代表已经实现图推断。评估另有空特征、分集合打乱标签负对照。

攻击子进程只接收许可的训练/验证标签与匿名测试特征，父进程保留测试真值以计算指标。这是输入隔离，不是操作系统沙箱。当前假定已知实验窗口，未自动从长期混合交易中切分任务。

结果应同时看 coverage、knownLabelCount、knownLabelAccuracy、unknownOnlyTest 和 warning。所有测试类别未知时，全拒识的 unknown 指标满分不表示识别任务。预算区间无限宽表示校准资料不足，不能写成精确预算恢复。

36 样本覆盖 3 任务×3 策略×2 预算×2 重复，12 成功、24 失败，记录全部保留，18/6/12 分组切分。它只验证管线，不能据此宣称真实 Agent 支付已被稳定识别。本地 Qwen 实测失败也保留，具体结论以[本版测试报告](V0.17.0-TEST-REPORT.md)为准。

本版能固定采购环境比较 exact、batch 和其他已适配部署产生的可见记录，尚未集成地址轮换、金额隐藏、随机延迟、PrivateX402、A402 或 TACEO 防御。批量结算已可运行，不等于已证明能够隐藏任务、预算或策略。

## 7. CLI 与源码复现

在包根目录 PowerShell 中执行：

```powershell
.\runtime\node.exe scripts/research-cli.mjs run examples/research/task.json data-research-cli/demo
.\runtime\node.exe scripts/research-cli.mjs matrix examples/research/matrix.json data-research-cli/matrix
.\runtime\node.exe scripts/research-cli.mjs evaluate data-research-cli/matrix
.\runtime\node.exe scripts/research-cli.mjs verify "data-research-cli/demo/<runId>"
```

`run` 和 `matrix` 会在指定输出父目录内创建 UUID 子目录；每个运行子目录必须为空。`verify` 参数应指向含 `config.json` 与 `integrity.json` 的单次 UUID 目录，它验证封存字节，不恢复执行。`evaluate` 第三个参数可选，用于指定报告文件；省略时写入输入目录的 `private-evaluation.json`，该报告包含真值，不能作为公开攻击输入。

`RESEARCH_BACKGROUND=1` 可启用每次采购前 1 笔同代币背景。真实 API 的密钥由 `RESEARCH_MODEL_API_KEY` 注入；本地模型配置目录可用 `RESEARCH_MODEL_DATA` 指定。`task.json` 是单次示例，`matrix.json` 是 3 任务×6 次重复的 18 运行示例，不等于测试报告中的 36 样本全因子矩阵。若需比较策略和预算，在 `factors` 增加 `strategy`、`budgetBase`；若需比较支付部署，分别设置 `base.payment` 执行不同矩阵。

开发者安装与回归：

```powershell
pnpm install --frozen-lockfile
pnpm run setup:research
node scripts/setup-runtime.mjs
pnpm run build:budget
pnpm run build
pnpm run test:unit
pnpm run test:research:chain
pnpm run typecheck
```

在解压后的完整 Windows 便携包目录另行运行 `.\runtime\node.exe tests/research-portable.mjs`，可检查六配置、导出和评估；这项验证强调无 `node_modules` 的运行条件，不能仅用开发工作树代替。源码开发使用系统 Node；`setup-runtime.mjs` 不安装 `runtime/node.exe`。

固定依赖：x4022.30.0、mppx0.18.0、viem2.57.4、OpenZeppelin5.6.1、solc0.8.30。支付依赖与既有框架依赖隔离，锁文件位于 `packages/payment-adapters/`，发布包运行桥已打包。源码测试需要开发依赖，便携运行不需要。

## 8. 验收与限制

本次单元、真实链支付、ERC 托管、引擎、便携配置和原有功能回归结果见[测试报告](V0.17.0-TEST-REPORT.md)。每个套件按自身范围独立记录，不重复累加为总数；记录完整、付款成功、任务成功与推断有效性分别判断。

软件包 `release-manifest.json` 和 ZIP SHA-256 用于核验交付，实验 `integrity.json` 用于核验封存记录。发布的脱敏测试摘要与证据哈希索引见 [test-results/v0.17.0](test-results/v0.17.0/summary.json)；本机原始实验包与私有真值不因发布测试报告而自动公开。

遇到 unknown/requires_attention 时保留预算占用并检查回执，禁止盲目重新付款。batch SDK 通道内存状态不能跨进程自动恢复。windowGasUsed 包含整个采集窗口的初始化/背景交易，不称 Agent 净 gas。

当前独立检查器验证台账与公共引用一致性，不是所有支付语义的形式化证明；RPC 未做共识认证。公开图尚未完整解码内部原生资产转移。未完成生产网络、Mac真机、并发用户、自动窗口分段、OS沙箱及完整隐私支付部署验证。
