# V0.15.1 操作手册

## 1 本版的使用范围

V0.15.1 是针对《V0.14 增量实现方案与验收标准》修订 2 的预览实现。它在已有 V0.15 程序中新增任务与 Agent 控制路径，保留原单 Agent 实验和 V0.15 的购买 Agent 服务入口。发布标签没有退回 V0.14，也不覆盖原压缩包。

新任务中心将任务定义、已发布 Job、具体 Execution 和 Agent 配置分开管理。用户可先发布任务，之后再启动独立 Agent 进程并分配角色。控制服务管理本地链、调度、持久记录和检查；各 Agent 进程持有自己的钱包与模型配置，按执行建立会话。

本版是 NOT_FULLY_ACCEPTED 预览版。每份验收报告只证明其自身 buildHash 和实测范围；先与交付 `build-info.json.sourceHash` 核对，不能仅凭 `docs/acceptance-v014/` 这个目录名认定是最终构建。证据关系见 `docs/验收证据索引_V0.15.1.md`。不能把前一版本的报告、本次某一正常示例或协议夹具当作 AT-01 至 AT-36 全部通过的证据。没有真实模型凭据、macOS 实机和独立人工核验条件的项目保留 BLOCKED。其他未完成子条件同样不得算通过。

## 2 安装与启动控制服务

1. 用原目录的 `stop.cmd` 关闭旧服务，备份旧版数据。
2. 将新 ZIP 完整解压到新目录，不覆盖正在运行的旧目录。
3. 在解压目录双击 `start.cmd`，打开 `http://127.0.0.1:4317`。
4. 双击 `open-task-center.cmd` 打开本实例的任务中心管理入口。

任务中心使用独立的本机管理员身份。`open-task-center.cmd` 读取本实例数据目录中的 `control-admin.token`，通过本地 URL 片段初始化页面；页面随即清除片段，再换取 HttpOnly、SameSite=Strict 的浏览器会话。后续 TaskCenter API 使用该会话。旧 `/api/health` 返回的 CSRF 值不是 V2 管理员身份，Agent Bearer 凭据也不能作为管理员读取全量执行或导出。会话失效或控制服务重启后，重新运行 `open-task-center.cmd`。不要分享管理员入口片段或令牌文件。

入口脚本会核对端口上的构建与数据目录；不匹配时拒绝打开，防止误连其他版本。

Windows 包使用随包的 Node 与 Anvil；无需系统 Python、Docker 或 Solidity 编译器即可运行。实现按 Node 24.19.0 验证 SQLite 适配层。端口被其他版本占用时，应先关闭旧实例，或在启动前为本实例同时设置不同的 `LAB_PORT` 与 `LAB_CHAIN_PORT`。

发布任务或创建离线 Agent 配置不要求先启动链。任务完成角色确认并获调度后，控制服务才准备执行环境。启动一个 Agent 也不会重置链。只有任务的环境策略可以要求恢复独立初态。

## 3 先发布任务

在左侧“发布任务”中选择模板、环境策略和参数，点击“发布任务”。此操作创建 published Job；不会自动启动 Agent、调用模型或提交资金交易。

| 模板 | taskType | 新任务中心的当前执行方式 |
|---|---|---|
| 查询余额 | balance | 脚本 LegacyTaskAdapter |
| 转账 | transfer | 脚本 LegacyTaskAdapter |
| 授权 | approve | 脚本 LegacyTaskAdapter |
| 兑换 | swap | 脚本 LegacyTaskAdapter |
| 兑换后存入 | swap_deposit | 脚本 LegacyTaskAdapter |
| 双 Agent 原子换币 | peer_swap | 脚本或双模型独立会话 |

新任务中心的五类旧模板当前为脚本适配。原单 Agent 入口继续保留其模型实验功能；不要把任务中心中显示的“执行方式”理解为所有旧模板都已完成独立进程模型迁移。

六类内置模板各有随包版本目录 `tasks/<taskType>/1.0.0/`，包含 manifest、参数 schema、任务定义快照、UI schema、角色提示词和默认 fixture。原子换币目录为 `tasks/peer_swap/1.0.0/`。这些是固定模板资料，不允许通过任务包上传并执行任意 JavaScript；新增业务能力仍需对应已安装工具与检查器。

金额使用人类可读的十进制字符串，例如 `10`、`0.5`，不是最小单位整数。代币精度为 6 位。负数、超精度、科学计数法和未知字段应在发布或分配前被拒绝。相同任务版本不能用不同内容覆盖；Job 绑定发布时的版本与定义哈希。

原子换币默认公开条款为 10 A 换 20 B，有效期 300 个链上秒。Maker 的最低收款和 Taker 的最高付款分别填写私有目标。管理员能查看完整任务档案；公开 Job 响应与角色上下文应按权限投影。完整实验包可能含两方研究上下文，分享前应检查范围。

## 4 创建和启动独立 Agent

在“独立 Agent”中输入 `agent-a`，脚本实验可把模型接口、模型名称和 Key 留空，点击“创建离线配置”。对 `agent-b` 重复一次。创建配置不等于启动进程。

在各 Agent 卡片上点击“启动独立进程”。卡片显示在线状态、公开钱包地址、PID 和租约代次。控制服务与 A、B 应是三个独立进程。默认心跳间隔为 2 秒，超过 6 秒未收到心跳视为离线。Agent ID 长期保留，每次执行重新分配 agentRunId 和会话。

双模型实验应在创建各自配置时填写工具调用接口、模型名称和 Key。允许两方使用同一个供应商、模型和 Key；它们仍有独立钱包与历史，但可能共享供应商额度。当前页面没有配置编辑功能；不要在执行中手工改钱包、任务版本或配置文件。

配置默认位于 `data/agents/<agentId>/`，或 `LAB_DATA_DIR/agents/<agentId>/`：

- `profile.json` 保存公开配置。
- `wallet-secret.json` 保存本机签名器秘密，由 Agent 读取；控制端不读取钱包秘密。交易意图准备与提交 HTTP 接口已实现，实际路径为 `POST /api/v2/tx-intents` 与 `POST /api/v2/tx-intents/<intentId>/submit`；接口权限和签名后广播顺序见 `docs/control-api_V0.15.1.md`。
- `model-secret.json` 单独保存该 Agent 的模型配置与 Key。
- `identity.token` 是本机控制服务的身份凭据。
- `outbox/` 与 `checkpoints/` 保存未确认事件及执行边界。

这些运行目录含敏感材料，不是可公开发布的数据集。不要将它们当作普通实验包分享。

需要从独立终端启动时，应先通过 GUI 或 API 完成配置和身份创建。默认 `agent-a`、`agent-b` 可分别双击 `start-agent-a.cmd`、`start-agent-b.cmd`；脚本读取相同的 `LAB_DATA_DIR` 与 `LAB_PORT`，不会写入钱包或模型秘密。也可以在解压根目录运行以下命令。不要将 `--init` 单独生成的钱包目录当作已注册的完整配置。

```text
runtime\node.exe dist\agent-worker.mjs --profile "data\agents\agent-a" --control http://127.0.0.1:4317
runtime\node.exe dist\agent-worker.mjs --profile "data\agents\agent-b" --control http://127.0.0.1:4317
```

设置了 `LAB_DATA_DIR` 或自定义端口时，应相应调整路径和 URL。同一配置不要同时启动两个实例。GUI 停止此 Agent 会请求停止并推进租约代次；停止进程不会撤回已经广播的交易。

## 5 分配角色与运行

在“角色分配”选择已发布 Job，原子换币分别选 Maker 和 Taker，点击“分配角色并开始”。单 Agent 旧模板只使用第一个角色选择框。

分配会检查在线状态、能力授权和钱包占用，先预留角色，再等待各 Agent 确认。默认 30 秒内未确认则撤回预留。角色完成确认的任务进入同链执行队列。一个钱包只允许一个活跃执行；资金或交易未厘清时，不能通过启动新实验绕过环境锁。

正常原子换币应得到：

| 对象 | 初始 A | 最终 A | 初始 B | 最终 B |
|---|---:|---:|---:|---:|
| Maker | 100 | 90 | 0 | 20 |
| Taker | 0 | 10 | 100 | 80 |
| 托管合约 | 0 | 0 | 0 | 0 |

双方精确授权在成交后应消耗为零。原生 ETH 用于 Gas，单列核算。Maker 的授权、建单和 Taker 的授权是分别发生的交易；只有最终 fill 内的双边交割是原子的，不能说整个实验只发一笔交易。

右侧显示 Execution ID、Job ID、耗时、工具和交易次数、资金状态、检查结果及原始证据。“查看完整图”使用 SVG 显示三条泳道，按 Execution 中的角色和 Agent 身份区分双方与控制/共享链证据。连线只取已记录的图边，不按时间邻近补造因果；缺少端点的关系会提示缺失，不补画。

点击节点或连线可查看原始事件及负载，长图可在容器中滚动。还可分别下载图 JSON、GraphML、节点 CSV 和关系 CSV，下载保留包内完整数据，不受页面滚动位置影响。

## 6 暂停与单步

“按工具单步推进”用于观察脚本或模型的一次动作。一次单步最多执行一个工具；等待轮次可能没有工具调用。

“暂停”以控制确认边界为准。请求已经发出不等于已确认暂停。确认后不应再开始新工具或新广播；已经广播的交易仍可确认，页面必须继续显示真实结果。

选择“提交交易前暂停”时，执行会停在提交门。此时应使用“继续”释放该门；单步不能代替对提交门的恢复。连续点击按钮不应产生额外执行，写请求使用幂等键。

## 7 停止后先核对资金

“停止并对账”只撤销后续决策和新操作，不自动退款，也不撤回已广播交易。

- 未建单且无待确认交易，可以停止结束。
- Maker 已托管但未成交时，应显示 `requires_attention`，保留环境锁。
- 订单仍可取消时，点击“取消并清退”；到期后点击“到期清退”。
- Pending 或 Unknown 先“重新对账”，必要时“出块并对账”。
- 只有退款回执确认、资金状态明确之后，才应解除锁。

订单期限按区块时间计算，与屏幕耗时不同。可设置出块数和每块推进秒数验证到期边界。到期本身不会自动发退款交易。不要以重置链或更换 nonce 的方式“重试付款”。

链失联、链身份改变、日志写入失败或广播不明时，应保留未知及待处理状态。无法核对存活原链时，不应静默创建新链继续旧任务。

## 8 崩溃后的恢复

控制端使用 SQLite 保存 Job、Execution、租约、消息、意图、命令和事件出站状态，原始事件另行归档。Agent 在自己的目录保存检查点与待确认事件。

恢复必须使用原版本、原 `LAB_DATA_DIR` 和对应端口。重新打开页面后先查看执行状态与诊断；对 `recovering` 或 `requires_attention` 先对账，不要直接发布替代付款。存活原链的连接需通过链身份、固定区块与合约代码核对，不能只信旧 PID。

Agent 重启后会重新注册并取得新租约，旧租约请求应被拒绝。恢复应保留原执行上下文及已执行副作用；不能因结果回传丢失再付一次。当前预览版的具体崩溃点覆盖，以验收报告为准。未通过的恢复用例不得解释为“任意时刻均可无损续跑”。

独立任务可点击“新建初态重跑任务”，得到新 Job 和新 Execution，并关联父执行。连续模式缺少可恢复共同快照时，会拒绝原样重跑；不能把改成独立初态的运行当作复现连续起点。

## 9 导出与离线检查

已结束且资金明确的执行可导出完整实验包。未封存的执行只能显式导出 `incomplete` 诊断包。诊断包是定位材料，不是完整验收证据。

包内包括任务定义、Job 与 Execution、事件流、内容寻址负载、初末状态、检查标签、交易与回执、执行轨迹及图数据。哈希用于检查内部文件是否改变，不证明采集器诚实，也不认证数据发布者。

在解压根目录运行：

```text
runtime\node.exe dist\cli.mjs doctor
runtime\node.exe dist\cli.mjs verify "执行包.json"
runtime\node.exe dist\cli.mjs replay "执行包.json"
runtime\node.exe dist\cli.mjs check "执行包.json"
```

`doctor` 检查版本、Node、SQLite 与 V0.15 受保护文件哈希，不连接模型或链。`verify` 检查内部清单、事件与来源引用；`replay` 输出已记录事件；`check` 用封存证据重算检查。离线 check 不是实时链上复核。业务检查未通过时退出码为 2，不应因为这条命令产生输出就记为成功。

任务中心的“离线打开”只读浏览器本地文件，检查哈希后展示记录，不继续轮询执行或提交控制。原单 Agent 历史格式仍由原 reader/CLI 路径处理。旧原始文件不应被转换器覆盖。

## 10 备份与验收

最稳妥的备份顺序是：停止新任务分配，处理待确认交易和未结托管，记录链身份与执行 ID，停止相关服务，再复制完整数据目录。运行中不要只复制 `control.sqlite` 而遗漏 WAL、Agent 检查点或待发事件。备份必须保护 `wallet-secret.json`、`model-secret.json`、`identity.token` 和数据目录根部的 `control-admin.token`，公开证据优先使用脱敏导出包。

验收入口使用新建隔离目录，不连接已有研究数据：

```text
runtime\node.exe scripts\acceptance-v014.mjs --case AT-14 --data-dir "data-acceptance-at14" --report "docs\acceptance-at14"
runtime\node.exe scripts\acceptance-v014.mjs --suite core --report "docs\acceptance-v014"
runtime\node.exe scripts\acceptance-v014.mjs --suite full --report "docs\acceptance-v014-full"
```

验收脚本中的目录名称需要包含 `acceptance`。`--case` 或 core 不会证明其他未运行用例通过；full 的结果也必须逐项检查。最终报告包含 `acceptance-summary.json`、`acceptance-cases.csv` 和 `machine-info.json` 等材料。Windows 与 macOS、协议夹具与真实模型、开发者自测与独立人审分别记录。

## 11 V0.15 服务购买

“购买 Agent 服务”继续使用 V0.15 原实现及其操作手册：Buyer 购买固定区块余额报告，Provider 交付，独立 Evaluator 验收，事后 Checker 检查质量与资金。不要将这一保留路径误称为已迁入新任务中心的独立进程服务交易。

保护清单为 `docs/v015-protected-baseline.json`，其中 11 个受保护文件已逐项核对为未改动。`doctor` 的 `serviceV015Unchanged` 应为 true；该字段是文件级一致性检查，仍需结合 V0.15 功能回归报告确认整包兼容。

## 12 源码与重新构建的验收边界

`vendor/legacy-source/` 保存固定提交的原始基线，42 个受跟踪文件与旧构建清单哈希匹配，其中 12 个为原始 TypeScript 源文件。新增控制运行时为 ESM；`pnpm typecheck` 只严格检查 `tsconfig.control.json` 指定的接口与类型测试，不检查完整运行时。`pnpm build` 编译合约并生成兼容桥，也不等于完成全部运行时 TypeScript 迁移或第三方干净源码重建。

重新编译合约时，安装固定 solc 0.8.30 或设置 `SOLC_JS_PATH` 指向离线编译器；脚本不依赖私有 tools 目录、不自动下载。发行包已有合约产物可直接运行。打包排除 build 与 data* 等运行诊断目录和凭据，数据备份与发行 ZIP 分开保管。

尚未完成的完整 TS 运行时验收、真实模型 10 次尝试、macOS 实机、独立人工核验，以及未运行的恢复与故障注入子条件，必须保留未完成状态。没有最终构建对应证据时，不用历史报告补作通过。
