# Managed local inference (V0.16.0)

This module adds a managed Qwen3 4B inference backend to the existing Agent. It
does not replace AgentKit, LangGraph, the transaction tools, or the independent
checker. Remote API model configuration remains supported by the caller.

## Assets and setup

The pinned Q8_0 model in `assets.json` is 4,280,404,960 bytes. It is the Ollama
Qwen3 4B Instruct 2507 artifact, not a differently packaged GGUF with the same
display name. The full SHA-256 is authoritative. Model weights and inference
binaries must not be committed to Git.

Run `node scripts/setup-local-model.mjs --help` for explicit import and resumable
download commands. Importing prepared files works without internet. Installation
never occurs as a side effect of starting the platform or selecting Local.

The operator supplies the matching llama.cpp executable and dependencies for
Windows or macOS. Windows Vulkan b12019 is the tested runtime. macOS has process
and path support but requires its own native validation; it cannot use the Windows
binary. A GUI import with `pinRuntime: true` hashes the executable and adjacent
DLL/dylib/so libraries. Importing a local hash records identity, not publisher
authenticity. Startup rechecks pinned bytes before launching a process.

## Service interface

```js
const service = new LocalModelService({
  dataDir,
  busy: () => anyExperimentActive,
  // Alternatively, beforeChange() may throw while mutations are disallowed.
});
const resolved = await service.resolveModel({ provider: 'local', temperature: 0 });
const cursor = await service.evidenceCursor();
// Execute the experiment with resolved.model/baseUrl and no remote key.
const evidence = await service.captureEvidence(resolved, cursor);
await service.shutdown();
```

`resolveModel()` returns remote (`provider: 'api'`) input unchanged. Local input
must not supply an API Key or a remote endpoint. Local requests use only the
service-owned loopback endpoint; failed startup never falls back to the remote
provider. If already resolved configuration is reused for rerun, its endpoint is
accepted only with a matching local manifest. Model/runtime/template hashes,
runtime dependency hashes, and runtime settings must match. Owner IDs, PIDs and
session log paths can change after a restart.

The HTTP adapter `handle(req, res, pathname, body)` returns whether it handled the
request. **The enclosing server must enforce its normal management authentication
before invoking it**. Available routes:

- `GET /api/local-model/status` or `/config`: status, configured paths, hashes,
  validation, owned PID and evidence references.
- `POST /api/local-model/configure` or `/config`: `modelPath`, `serverPath`,
  `serverSha256` or explicit `pinRuntime: true`; optional `contextSize`,
  `maxOutputTokens`, `threads`, `gpuLayers`, `port`, `templatePath` and
  `templateSha256`.
- `POST /api/local-model/start`: validate then launch, or reuse the owned process.
- `POST /api/local-model/stop`: stop only this instance's exact child handle.

Default settings are context 16,384, output cap 768, six threads, automatic GPU
offload, one inference slot, reasoning off, and port 8495. A busy experiment blocks
reconfiguration/stopping. `shutdown()` bypasses that guard for process cleanup.
An occupied port is refused; the service never adopts or terminates another
listener. A stopped service can restart the same pinned configuration for rerun.

## Evidence semantics

Each owned runtime session has an immutable launch identity, full runtime
properties (including the actual chat template), SHA-256 validation results,
arguments, lifecycle JSONL and stdout/stderr logs. `model.localRuntime` embeds the
properties, so exported configuration does not depend on the original absolute
file paths to recover a template.

The experiment collector separately records actual model HTTP requests/responses,
tool calls, chain events and checks. `captureEvidence()` returns byte-exact base64
snapshots with content hashes and byte ranges; it opens only files generated by
this service. A cursor captures new runtime log bytes after a run starts; without
a cursor the whole session is captured. Runtime logs are explicitly scoped to a
**shared inference session**, not attributed exclusively to one experiment.
Concurrent runs can have overlapping ranges. These snapshots must be saved in the
experiment package, not reduced to external path references.

No internal model thoughts are inferred or manufactured. Local execution improves
control of model bytes and settings, but does not promise deterministic outputs or
successful completion of every task.

## Verification

`node --test tests/local-model.test.mjs` exercises isolated temporary files, real
owned subprocesses, local HTTP health/properties, concurrent start, cancellation,
foreign-port refusal, hash mutation, busy guards, rerun identity and download range
verification. These are service regression tests, not evidence that a fake test
runtime is a real LLM. Real Qwen/chain regressions are reported separately.
